Structs and Unions

1. Arr: the fundamental data container

typedef struct {
   float* values;
   int* shape;
   int* strides;
   int ndim;
   int size;
} Arr;

Think of Arr as the physical memory view of a tensor - it says where numbers live, how they are shaped, and how to walk through them.

Components:

float* values:

A pointer to the raw data, usually stored in a flat 1D contiguous array in memory.

Example: if you have a 2×3 tensor, it's still stored linearly like [a11, a12, a13, a21, a22, a23].

int* shape:

Describes how to interpret that flat memory. For the 2×3 case, shape = [2, 3].

The number of elements in shape equals ndim (the number of dimensions).

int* strides:

The stride tells how many steps (in memory) you move to go from one element along a given dimension to the next.

For a row-major array:

shape = [2, 3]
strides = [3, 1]

Meaning: to move one row down, jump 3 elements; to move one column right, jump 1 element.

This is what allows views, slicing, transposing, and broadcasting without copying memory.

int ndim:

Number of dimensions (rank of the tensor).

int size:

Total number of elements = product of all shape dims.

You can think of Arr as describing a map from N-D index => 1-D memory address.

2. Arg: the generic operation argument

typedef union {
   int ival;
   float fval;
   int* ilist;
} Arg;

This is a clever design: operations (like sum, mean, reshape, etc.) sometimes require extra parameters.

For example:

  • mean may need axis (an integer)
  • matmul doesn't need any
  • reshape might need a list of new dimensions

But all these argument types differ - some are ints, some floats, some lists.

A union allows you to store any one of these types in the same memory slot.

It's like a shape-shifting container that says, "I might be an int today, a float tomorrow."

3. Tensor: the higher-level abstraction

typedef struct Tensor {    Arr* data;
   Arr* grad;
   int op;
   struct Tensor* prevs[MAX_PREVS];
   int num_prevs;
   Arg args[MAX_ARGS];
} Tensor;

Now we step up from raw data to computational graphs - this is the abstraction that lets you do autodiff (automatic differentiation).

Fields explained:

Arr* data:

This points to the actual numerical data (the forward-pass result).

For example, if this tensor represents C = A * B, then data holds the result of that multiplication.

Arr* grad:

Gradient of this tensor with respect to some loss function.

During backpropagation, this gets filled in.

At the start of training, all grad arrays are zero.

int op:

Identifies which operation created this tensor - maybe MATMUL, RELU, ADD, etc.

This allows you to know how to backprop through it later.

Tensor* prevs[MAX_PREVS]:

These are the input tensors that were used to compute this tensor.

For example, if this tensor C = A + B, then:

prevs = [A, B] num_prevs = 2

That's how you reconstruct the computational graph - a directed acyclic graph (DAG) of operations.

int num_prevs:

How many previous tensors were used.

Arg args[MAX_ARGS]:

Additional arguments that modify the operation (axis, stride, scalar values, etc.).

Think of them as operation metadata.

4. How it all ties together (intuitively)

Imagine you call:

Tensor *A = create_tensor_from_array(...);
Tensor *B = create_tensor_from_array(...);
Tensor *C = tensor_add(A, B);

tensor_add creates a new Tensor C.

It allocates a new Arr for C->data.

Sets C->op = ADD.

Records that C->prevs = [A, B].

Stores any args (none in this case).

Later, during backpropagation, you'll do something like:

if (C->op == ADD) {
   A->grad += C->grad;
   B->grad += C->grad;
}

Each operation in your system builds nodes in the graph automatically.

You can then call backward() on the final loss tensor, and the engine recursively traverses prevs[], applying the correct gradient rule per op.

That's the magic: the graph builds itself as you do math, and backprop unwinds it in reverse.
